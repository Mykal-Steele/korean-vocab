# Korean vocab site: notes for Claude

This repo is a static study site for beginner Korean. It is published at
`adorio.space/learn-korean`. Changes reach that page only through merges to `main`.

## Where things live

- `assets/js/data.js` holds the words (`WORDS`) and categories (`CATEGORIES`).
  Almost every content change happens here. The field meanings are in the comment at the top.
- `index.html` is the page markup. Its CSS and JS are listed as `<link>` and `<script>` tags.
- `assets/css/styles.css` and the other `assets/js/*.js` files are hand-written source.
- `assets/audio/*.mp3` are the spoken clips. `assets/js/audio.js` maps each spoken string to its clip.
- `assets/css/fonts.css` is generated by `tools/build-fonts.py`.
- `tools/check-data.js` validates `data.js`. `build.py` runs it and refuses to build on failure.
- `dist/` is generated. Do not edit it by hand.

## Generated files: do not hand-edit

- `assets/js/audio.js` (regenerated by `tools/build-audio.py`)
- `assets/audio/*.mp3`
- `assets/css/fonts.css` (regenerated by `tools/build-fonts.py`)
- everything under `dist/`

## Adding or changing a word

1. Edit `assets/js/data.js`. Every field the checker needs is listed at the top of the file.
2. Run `node tools/check-data.js`. Fix anything it reports.
3. If the word or its example sentence has no clip yet, CI renders it. On a PR from a branch in
   this repo, the `audio` job renders the missing clips and pushes a commit to your branch. Pull
   the branch before you make more edits. Forks don't get this job, so a PR from a fork has no
   audio. Do not install gTTS or Piper to render clips yourself unless the owner asks.
4. Look at the page locally (see below).

## Viewing the site the way Adorio shows it

Run this from the repo root:

    python3 tools/serve.py

It builds the hosted layout into `dist/local` and serves it on port 8000. Open
`http://localhost:8000/learn-korean`. This is the same URL Adorio serves, and the
asset URLs have the same structure as on R2.

The server builds once when it starts. After you edit a file, stop the server and start it
again. Run it in the background so you can keep working.

To check the page in a browser, open `http://localhost:8000/learn-korean` with the browser
tools, take a screenshot, and read the console for errors. Check the category filters, the
card flow and one audio clip. Use the browser tools only for this local URL.

## Git and deploys

- Work on a branch and open a PR. Do not push to `main`.
- `main` needs one approving review from someone other than the PR author. The owner can bypass this.
- Merging to `main` deploys the site right away. There is no approval step.
- A deploy builds the site, uploads it to R2, and checks that the stored entry page matches the
  build. It reads the copy from R2, not the public URL, because Cloudflare adds a script to HTML
  served on the adorio.space zone.
- Do not add or print R2 credentials, Cloudflare tokens or `.env` values. CI holds them.
- Do not change `adorio.space` code from this repo. The Adorio route already reads the
  entry page from R2.

## What the hosted build does

- `python3 build.py --site` writes `dist/site/learn-korean.html` (the entry page, about 20 KB) and
  `dist/site/learn-korean/` (CSS, JS and audio, each named by a hash of its contents).
- Uploads send the assets first and the entry page last, so the page never points at a
  file that is missing.
- Assets get long cache lifetimes. The entry page is revalidated on every visit.
- Each audio clip is named by a hash of its bytes. A re-rendered clip gets a new URL.
  This is why a clip can be cached for a year without going stale.

## Keep the artifact copy working

`python3 build.py` also writes `dist/artifact.html`, a single file with the audio embedded as
data URIs. A separate host uses it and blocks all other requests. Don't add anything to the
page that needs a second request, unless the artifact copy is also changed to handle it.
